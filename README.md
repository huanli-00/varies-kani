# varies-kani

A fork of [Kani](https://github.com/model-checking/kani) for verification suites
generated by `cargo-varies`. It adds dependency-aware harness scheduling,
verification-time pruning, compile-error recovery, time budgets, and HTML reports.

The upstream base is `8ec44d0237377bd848f563ea0ef960daae1c2a7e`.
The compiler and driver version is 0.65.0, using Rust `nightly-2025-10-23`.
Full verification requires synthesized sequence metadata; ordinary Kani proof
crates without that metadata are not supported by this fork's scheduler.

## Build From Source

The documented build environment is Linux with rustup, CBMC 6.7.1, and Kissat
4.0.1. The Ubuntu setup script installs system dependencies with sudo.

```bash
git clone --recurse-submodules https://github.com/huanli-00/varies-kani.git
cd varies-kani
./scripts/setup/setup
cargo build-dev -- --release
export PATH="$PWD/scripts:$PATH"
cargo varies-kani --version
```

The retained Charon submodule is needed by the compiler's optional LLBC backend.
The build helper produces the compiler, driver, and verification libraries in
`target/kani/`.

## Verify a Generated Suite

Run from the generated harness crate so that `varies_meta/` is discovered:

```bash
cd /path/to/generated-harness
cargo varies-kani --only-codegen
cargo varies-kani -Z unstable-options \
  --global-timeout 30m --target-timeout 10m --html-output
```

To enable coverage instrumentation and coverage-based pruning:

```bash
cargo varies-kani -Z unstable-options --coverage -Z source-coverage \
  --global-timeout 30m --target-timeout 10m --html-output
```

`--manifest-path` selects the Cargo manifest, but does not select the metadata
directory. Set `KANI_SYNTHESIZED_META_DIR` to an absolute metadata directory when
running elsewhere. `scripts/verify-generated.py` can record the command and log
in the current working directory.

The scheduler visits dependency levels across targets. Select a target with
`--target-idx`; select pruning with `--synth-pruning`:

| Mode | Behavior |
| --- | --- |
| `coverage` (default) | Failure propagation, coverage-based successor selection, and target timeout pruning |
| `failure-only` | Failure propagation and target timeout pruning |
| `disabled` | Execute all scheduled sequences after their parents finish, including after failures |

Disabled pruning also disables target timeout pruning. Global and individual
harness timeouts still apply. The global budget starts at verification scheduling;
it does not bound the initial Cargo compilation. Target budgets track accumulated
verification work rather than initial Cargo compilation.

`--error-recovery` temporarily stubs generated harness files that fail compilation.
Recovered/skipped harnesses are not successful proofs. `--assert-as-assume` and
`--skip-unsupported-check` weaken proof obligations; results must be interpreted
with those options in mind. See `cargo varies-kani --help` for available controls.

With `--html-output`, reports are written to `kani_results/`.

## Metadata Contract

The metadata directory contains `<dataset>_api_sequences.json` files, each holding
an array of sequences. Harness source names such as `test_<dataset>0.rs` identify
the dataset and sequence index.

Sequence fields are `index`, `predecessor`, `is_basic`, `successor` (an array),
and `target`. Optional `parents` adds multiple predecessors; optional `cost`
defaults to zero. A basic sequence, or a self predecessor, denotes a root.
Legacy roots with predecessor zero must carry `is_basic: true`.
The producer's `construction_cost` field is not an alias for `cost`.

Keep generated source names and metadata together. Missing or incompatible
metadata prevents verification scheduling.

## Coexistence With Official Kani

| Resource | varies-kani |
| --- | --- |
| Cargo command | `cargo varies-kani` |
| Standalone command | `varies-kani` |
| Launcher package | `varies-kani-verifier` |
| Installation root | `~/.varies-kani/` or `VARIES_KANI_HOME` |
| Cargo verification artifacts | `<target-dir>/varies-kani/` |

Official `kani`, `cargo kani`, and `KANI_HOME` remain separate.
`--force-build` clears this fork's Cargo artifact directory.
Standalone compilation is available with `varies-kani file.rs --only-codegen`;
full standalone verification also needs synthesized metadata.

The aliases in `scripts/upstream/` exist for inherited regression tests.
Do not add that directory to your shell PATH.

## Local Bundle Installation

After building the source checkout:

```bash
cargo bundle -- 0.65.0
cargo install --locked --path .
cargo varies-kani setup --use-local-bundle \
  ./varies-kani-0.65.0-x86_64-unknown-linux-gnu.tar.gz
```

Use the archive matching your host architecture. Bundles include a
`varies-kani-version` marker and install under `varies-kani-<version>/`.
Automatic setup downloads from this repository's Releases using
`varies-kani-<version>` tags, and requires a matching published release asset.
Installing launchers alone does not build or install the compiler.
To reuse an existing matching Rust toolchain, setup also accepts
`--use-local-toolchain /absolute/path/to/toolchain`.

## Development

```bash
cargo fmt
cargo test -p varies-kani-verifier -p kani-driver
cargo build-dev -- --release
cd fixtures/synth-smoke
../../scripts/cargo-varies-kani --synth-pruning disabled
```

Core code lives in `kani-driver/` (scheduling and verification),
`kani-compiler/` (compiler), `library/` (verification libraries), and
`tools/build-kani/` (build and bundle tooling). Inherited compiler regression
tests remain in `tests/`; some assume upstream verification semantics.
See [CONTRIBUTING.md](CONTRIBUTING.md) and [AGENTS.md](AGENTS.md).
