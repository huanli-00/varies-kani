# varies-kani

## Scope

This fork verifies harness suites generated by `cargo-varies`. Preserve the
synthesized-suite contract when changing compiler or driver behavior.

## Code Map

- `kani-driver/src/project.rs`: metadata loading, dependency graph, scheduling,
  coverage-based pruning, and generated-source compile recovery.
- `kani-driver/src/harness_runner.rs`: verification loop, budgets, results,
  and HTML reports.
- `kani-driver/src/args/mod.rs`: CLI options and validation.
- `kani-driver/src/call_cargo.rs`: Cargo invocation and fork artifact directory.
- `kani-compiler/` and `library/`: inherited compiler and verification libraries.
- `src/`: installed launchers and bundle setup.
- `tools/build-kani/` and `scripts/`: source builds and packaging.

## Contracts

- Read `*_api_sequences.json` from `KANI_SYNTHESIZED_META_DIR` or
  `./varies_meta`. Match dataset/index to generated harness source names.
- Preserve `index`, `predecessor`, `is_basic`, `successor`, and `target`;
  `parents` and `cost` are optional. Root predecessor sentinels require
  `is_basic` unless the predecessor is the sequence's own index.
- Coordinate schema changes with the generator. `construction_cost` is not
  currently parsed as `cost`.
- Scheduling is breadth-first across targets and respects all parent
  dependencies. Keep graph status propagation and report rendering consistent.
- `coverage` prunes by coverage, failure, and target budget; `failure-only`
  omits coverage selection; `disabled` also disables failure and target-budget
  pruning. Global and harness budgets still apply.
- The global budget starts at scheduling, after initial Cargo compilation.
- Full verification requires synthesized metadata. Do not silently substitute
  ordinary upstream verification when that contract fails.

## Namespace

Public commands are `cargo varies-kani` and `varies-kani`. Keep installations
under `VARIES_KANI_HOME` or `~/.varies-kani`, archives named `varies-kani-*`,
and Cargo artifacts under `<target-dir>/varies-kani`.
Require the matching `varies-kani-version` bundle marker.
`scripts/upstream/` aliases are private to inherited tests.

## Validation

After Rust edits, run `cargo fmt`, then focused tests:

```bash
cargo test -p varies-kani-verifier -p kani-driver
cargo build-dev -- --release
(cd fixtures/synth-smoke && ../../scripts/cargo-varies-kani --synth-pruning disabled)
```

Use `tests/launcher_namespace.rs` for installation isolation and
`fixtures/synth-smoke` for end-to-end scheduling. Keep changes scoped, retain
license notices, and add regression coverage for changed scheduling semantics.
